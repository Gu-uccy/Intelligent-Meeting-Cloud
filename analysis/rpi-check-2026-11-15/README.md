## 树莓派人脸性能

默认单尺度4×4 / 944维，YuNet检测0.6、五点比例0.85，完整处理同批624张CMU：579成功、45失败。固定登记192、标定217、test215；仅登记与标定选择阈值，写冻结文件后才提取test，未改候选或按test调阈值。

| 指标 | 实机结果 |
|---|---:|
| 已知正确 | 70/90（77.78%） |
| 已知拒识 | 20/90（22.22%） |
| 已知错认 | 0 |
| 未知误接受 | 2/125（1.60%） |
| 综合accuracy | 193/215（89.77%） |
| 432次完整处理平均 / P95 | 40.627 / 46.195ms |

计时含读取文件、解码、检测、对齐、预处理、特征和匹配，包含35次失败，不含HTTP/相机采集/设备动作；OpenCV4线程，采集服务同时运行。是同批低分辨率CMU上的**目标设备耗时**，不是现场相机准确率、3D渲染性能、门禁放行验收或新增独立样本。

首次部署缺少 `run_face_eval.py` 依赖，补齐后又触发Windows选择文件的精确阈值检查，均没有继续提取test特征（清单加载仍校验文件哈希）。Pi标定阈值0.9311644386168607，Windows为0.9311644386168618，差约1.11e-15，精确比较拒绝符合现有保护规则。没有放宽检查；使用新输出目录在Pi登记/标定上重新冻结后完成评估。

跨平台还存在最高约0.000288的相似度差，624行的检测成功与候选身份均相同。Pi标定正确80/96、未知误接受5/121；Windows为80/96、6/121。把Windows阈值直接应用到Pi标定CSV会使已知正确变成79/96，提示部署须在目标环境重新标定；两种阈值在原test均70/90、2/125，见 `platform-comparison.json`。这不证明跨平台分数逐元素一致。

`face-evaluation/`为最终实机记录；`face-evaluation-initial/`保留先前实机测量，其旧程序把`target_raspberry_pi`写死false，此元数据缺陷已改成读取`/proc/device-tree/model`，最终结果为true并记录实机型号。两次完整运行test计数相同，第一次平均39.977/P95 41.155ms，不能只选较快运行报告。

实际CMU照片经LAN `/api/face/verify` 完成提取，因无运行身份阈值返回422并保持拒绝；缺图422、无管理员令牌录入403均通过。服务仍空底库、无阈值/预约，`simulation-only`指人脸业务门控范围，并非人脸算法运行在模拟设备；离线阈值未写服务，未录入CMU人物或打开实物门。
