# 核心接口冻结清单（v1.0，第 8 周冻结）

> 第 8 周硬指标：把对外接口定下来，写进接口文档与 README（路径、参数、返回字段、错误处理）。第 9—12 周基于本版接口做工程化，**不再随意改字段**。
> 本清单依据仓库真实代码整理，字段与《状态字段表》一致。

## 一、冻结约定

| 项 | 约定 |
| --- | --- |
| 版本号 | `api-v1.0`（冻结日期：2026-11-08） |
| 变更规则 | 任何字段增删改必须先更新本文件 + `README.md` 变更记录，并注明原因与影响范围；未经记录不得改动 |
| 兼容策略 | 只允许**增加可选字段**；删除/改名/改类型视为破坏性变更，需升 v2.0 并保留 v1 一个版本周期 |
| 字段命名 | 统一 `snake_case`（传感器侧）与既有 Spring Boot 侧 `camelCase`（业务侧），两侧各自冻结，不互相混用 |
| 时间格式 | 传感器侧：`YYYY-MM-DD HH:MM:SS`（本地时区 +08:00）；业务侧：`YYYY-MM-DD HH:mm:ss` |
| 布尔字段 | 一律 `true/false`，**不再使用** `"open"/"closed"` 字符串（`door_status` 仅作历史兼容） |
| 错误处理 | 传感器侧用 HTTP 状态码 + `{"error": "..."}`；业务侧用 HTTP 200 + `{"code":1成功/0失败, "msg": "...", "data": ...}` |

## 二、传感器/环境接口（Flask 统一服务，端口 5000）

服务：`Flask/unified_meeting_room_system.py`；前端经 Vite 代理 `/sensor-api → /api`。

### 2.1 `GET /api/current`（核心，3D 唯一数据源）

**返回 200**（实测字段，17 个顶层 + devices 12 个）：

| 字段 | 类型 | 单位/取值 | 说明 |
| --- | --- | --- | --- |
| `temperature` | number | ℃（保留 1 位） | DHT11 温度 |
| `humidity` | number | %（保留 1 位） | DHT11 湿度 |
| `distance` | number | cm | HC-SR04 距离（模拟时有抖动） |
| `motion` | boolean | — | PIR 当前是否有人 |
| `presence` | boolean | — | 同 `motion`（兼容旧字段） |
| `motion_count` | number | 累计次数 | 本次服务启动以来触发次数 |
| `last_motion` | string | 如「8 秒前」 | 最近一次有人时间描述 |
| `light` | number | 0-255 | 光敏（PCF8591 或模拟） |
| `smoke` | number | 0-200 | MQ-2 烟雾浓度（模拟时 0-90，偶发 130-200） |
| `door_open` | boolean | — | 门禁状态（**冻结字段**） |
| `door_source` | string | `hardware`/`room-3d`/`control-page`/`auto` | 门状态来源，用于界面标注 |
| `devices` | object | 见 2.2 | 设备状态集合 |
| `temp_min` / `temp_max` | number | ℃ | 温度设定区间（当前 20 / 26） |
| `humidity_min` / `humidity_max` | number | % | 湿度设定区间（当前 40 / 60） |
| `timestamp` | string | `YYYY-MM-DD HH:MM:SS` | 采集时间（**前端据此判断数据新鲜度**） |

**返回 503**：`{"error": "Sensor data not available"}`（采集线程首轮取值完成前）。
**错误处理要求**：前端轮询连续失败 ≥2 次必须进入“断连态”；不得静默使用旧值继续渲染（缺陷 D-02）。

### 2.3 `POST /api/control`（控制）

请求体（`Content-Type: application/json`）：

```json
{"action":"manual","device":"door","state":true,"source":"room-3d"}
{"action":"manual","device":"lighting","state":true,"brightness":80,"source":"room-3d"}
{"action":"set_auto","enabled":true}
{"action":"set_params","temp_min":20,"temp_max":26,"humidity_min":40,"humidity_max":60}
```

| action | 必填参数 | 返回 |
| --- | --- | --- |
| `manual` | `device`（`door`/`lighting`/`cooling`/…，须属于 `devices` 键）、`state`(bool)、可选 `brightness`、`source` | 200 `{"success":true,"devices":{...}}` |
| `set_auto` | `enabled`(bool) | 同上 |
| `set_params` | `temp_min`/`temp_max`/`humidity_min`/`humidity_max`（int） | 同上 |

**错误码（实测）**：

| 场景 | 状态码 | 响应体 |
| --- | --- | --- |
| body 为空且无 `Content-Type` | **415**（实测）| Flask 默认 `Unsupported Media Type` 页面 |
| body 为空但带 `application/json` | **400** | `{"error":"Invalid request"}` |
| `action` 未知 | **400** | `{"error":"Unknown action"}` |
| 用 GET 访问 | **405** | Method Not Allowed |
| 未知路径 | **404** | 默认 HTML/JSON |

## 四、错误处理与降级总表（冻结，三端一致）

| 场景 | 传感器侧 | 业务侧 | 前端表现（要求） |
| --- | --- | --- | --- |
| 参数非法 | 400 `{"error":"Invalid request"}` | `code=0, msg` | 表单红字提示，不弹窗遮挡 |
| 未知动作 | 400 `{"error":"Unknown action"}` | `code=0, msg="未知操作"` | Toast 提示，保持页面 |
| 未授权 | — | HTTP 401 / `code=0` | 跳登录，携带原路径 |
| 无权限 | — | `code=0, msg="没有操作权限，请联系管理员"`（`GlobalExceptionHandler`） | 按钮禁用 + 提示 |
| 数据未就绪 | 503 `{"error":"Sensor data not available"}` | `code=0` | **断连横幅**，禁用控制，显示最后成功时间 |
| 超时（>5 s） | 前端 axios timeout=5000 | 同上 | 同上，并计入失败次数触发重连 |
| 服务不存在 | 404 | 404 | 断连横幅 + 重连倒计时 |

### D-07（冻结自检发现，中）：错误码与契约不一致

代码意图是「body 为 None → 400 Invalid request」，但 `request.get_json()` 在**没有 `Content-Type: application/json`** 时直接抛 415，因此空 body 请求实际返回 **415 + HTML 页面**，调用方拿不到统一 JSON 错误体。

修复（一行）：

```python
data = request.get_json(silent=True)   # 原为 request.get_json()
if not data:
    return jsonify({"error": "Invalid request"}), 400
```

回归标准：`POST /api/control`（无 body、无 JSON 头）→ 400 且响应体为 `{"error":"Invalid request"}`；脚本该项由 FAIL 转 PASS。
