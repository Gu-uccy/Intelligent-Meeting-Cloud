## 三、链路时序

```
T+0.0s   传感器采样并写入全局快照（sensor_loop 每 3 s）
T+0.0s   GET /api/current 返回该快照（含 timestamp）
T+0~3s   前端定时器触发，axios 请求 /sensor-api/current（超时 5 s）
T+0.1s   refreshSensorData 合并数据，roomState 重算
T+0.1s   updateSensorVisuals 修改 Three.js 对象属性，下一帧渲染
T+3.0s   下一次轮询；数据未变时画面保持不变
```

端到端延迟 ≤ 6 s（3 s 采集 + 3 s 轮询最坏叠加），单次请求耗时 14-16 ms。

## 四、联调覆盖的状态与结论

| 状态 | 触发方式 | 场景表现 |
| --- | --- | --- |
| 空闲 | 无人、门关、灯关 | 人形隐藏，门扇关闭，顶灯熄灭 |
| 有人 | `motion=true` | 人形出现并浮动，面板显示有人 |
| 门开 | `door_open=true` | 门扇旋转 93.6°，门状态灯转绿，来源文案随 `door_source` 变化 |
| 开灯 | `lighting=true, brightness=80` | 顶灯自发光点亮，亮度系数 0.35 + 80/100×1.35 |
| 温湿度越界 | `temperature >= 28` | 指示牌与空调模块变色，顶部读数同步 |
| 烟雾越界 | `smoke >= 60` | 报警信标与烟雾云触发，卡片显示数值 |

链路结论：状态值全部来自 `/api/current`，控制指令经 `/api/control` 写回并由场景呈现，闭环成立；异常提示与报警可见性两项列入 D-02、D-03 整改。

## 六、故障排查手册

| 现象 | 可能原因 | 排查动作 |
| --- | --- | --- |
| 右上角一直「模拟数据」 | 5000 未启动 / 代理目标错 | `Invoke-RestMethod http://127.0.0.1:5000/api/current`；查 `vite.config.js` 的 `VITE_SENSOR_PROXY_TARGET` |
| 页面能开但 3D 黑屏 | WebGL 被禁用 / 显卡驱动 | `chrome://gpu` 查看 WebGL；加 `--enable-unsafe-swiftshader` 验证 |
| 数据不更新 | 页面隐藏触发浏览器节流 / `sensor_loop` 停止 | 查 `data/unified_sensor_log.txt` 是否持续追加 |
| 门点了没反应 | 后端未返回 `door_open`，代码退回本地预览 | 看控制台 `Door servo endpoint is not available`；核对舵机 GPIO13/12 |
| 控制后 3 s 才变化 | 轮询周期 3 s | 正常行为，非缺陷 |
| 中文日志乱码 | 终端编码非 UTF-8 | `chcp 65001` 后重启服务 |
| 端口被占 | 上一次服务未退出 | `Get-NetTCPConnection -LocalPort 5000`，必要时结束进程 |

## 七、联调结论

1. 闭环成立：4 类状态均由接口数据驱动，控制指令经接口写回后由场景呈现；
2. 15 个步骤中 13 步通过，2 步暴露 D-02、D-03 并已给出整改方案；
3. 3D 链路与业务后端解耦，可独立演示与复现。
