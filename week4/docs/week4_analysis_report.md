# 第4周项目实践：数据分析报告

## 一、数据与分析口径总览

- 数据源：`data/processed/clean_data_v1.csv`（第3周清洗后的正式数据版本 v1，14113 条）
- 时间范围：2026-09-01 ~ 2026-09-28（4 周），每日 08:00—22:00 每 5 分钟采样
- 会议室：301（3楼东区，10人）、302（3楼西区，20人）、501（5楼多功能区，50人，维修中）
- 全部口径在每张图标题与本节中写明，结论数字均由脚本实际计算（可复现：`python scripts/generate_analysis_charts.py`）

## 二、图表与结论

### 图1：分时段占用率

文件：`charts/01_分时段占用率.png`

口径：2026-09-01~09-28 期间，每个整点小时（08:00—22:00）内 occupancy=1（有人）的采样数 ÷ 该小时有效采样总数（3 间会议室合并）。

结论：
- 高峰为 **10:00，占用率 42.9%**；9:00~11:00、14:00~17:00 两个时段占用率均高于 38%，与会议安排密集的上午、下午业务时段吻合；
- 12:00（午休，15%）与 21:00（13%）为低谷，20:00 后基本结束使用。

### 图2：各会议室占用强度

文件：`charts/02_各会议室占用强度.png`

口径：每间会议室“有人”采样数 ÷ 该会议室有效采样总数；并换算总占用小时数（每 12 条采样 ≈ 1 小时）。

结论：
- **301 占用率最高（44.4%，约 173 小时）**，为小组规模会议主用会议室；
- 302 次之（36.0%，约 141 小时）；
- **501 最低（6.5%，约 25 小时）**——501 在数据库中状态为维修（status=2），几乎不对外使用，与业务状态一致，可作为“占用率低→排查维修状态/空置资源”的管理线索。

### 图3：工作日 vs 周末占用率

文件：`charts/03_工作日vs周末占用率.png`

口径：工作日（周一至周五）占用采样数 ÷ 工作日有效采样总数；周末（周六、周日）同理。

结论：
- 工作日占用率 **38.5%**，周末仅 **5.1%**；
- 周末会议室基本闲置，建议关闭非必要的设备（照明/制冷）以节能，或将周末资源用于培训/加班预约放开。

### 图4：温度分布

文件：`charts/04_温度分布.png`

口径：清洗后温度有效采样（0~50℃ 内，14084 条）落在各区间的采样占比，2℃ 分档；20~26℃ 为综II自动控制逻辑（TEMP_MIN=20、TEMP_MAX=26）的舒适区间。

结论：
- 温度集中在 **26~28℃（31.7%）与 24~26℃（29.2%）**，30~32℃ 占 25.5%；
- **20~26℃ 舒适区间占比仅 9.5%**，多数时段温度高于舒适区间上限，制冷设备频繁开启；
- 与管理建议：提高制冷联动阈值或提前预冷，可将温度压回舒适区间并减少制冷能耗。

## 三、基线预测模型（baseline_model.py）

| 项目 | 内容 |
| --- | --- |
| 业务问题 | 会议室某时段是否“有人使用” |
| 基线方法 | 阈值基线：历史同时段（会议室×小时）平均占用率 > 0.5 → 判有人 |
| 小时口径 | 小时占用率 = 该小时“有人”采样数 ÷ 有效采样总数；小时标签 = 占用率 > 0.5 |
| 样本量 | 测试 294 个整点小时样本（7 天 × 14 小时 × 3 会议室）；训练 882（21 天 × 14 小时 × 3 会议室） |
| 切分方式 | 按时间切分：2026-09-01~09-21 历史，2026-09-22~09-28 测试 |
| 可复现命令 | `python scripts/baseline_model.py` |

测试集指标（n=294，实际运行结果）：

| 指标 | 数值 |
| --- | --- |
| 准确率 Accuracy | 0.8503（85.03%） |
| 有人判对 TP / 无人判对 TN | 44 / 206 |
| 有人误判无人 FN / 无人误判有人 FP | 25 / 19 |
| 有人类精确率 Precision | 0.6984 |
| 有人类召回率 Recall | 0.6377 |
| F1 | 0.6667 |
| 按会议室准确率 | 301：0.8265 / 302：0.7245 / 501：1.0000 |

分析：
- 501 因维修期几乎无人，基线“全判无人”即达 100% 准确率，说明该基线对稀有占用场景没有预测价值，需在后续模型中按会议室/业务状态加权或剔除维修期数据；
- 有人类召回率偏低，主要来自 302 会议室高峰时段占用不稳定；后续迭代方向：加入星期、节假日特征，或改用逻辑回归基线。

## 四、结果可见性

- 基线预测结果由 `scripts/publish_baseline_to_state.py` 写入**统一状态对象**（与第3周 `mock/state.json` 同构，见 `results/state_with_baseline.json`）；
- 3D 场景（`../Intelligent-Meeting-Cloud-main/FrontEnd/Intelligent_meeting_cloud/src/views/User/Room3D/index.vue`）轮询状态对象，按 `occupancy`（有人/无人）更新场景中人员模型、按 `devices.lighting` 更新灯光；
- Web 环境监测页（`src/apis/sensor.js` → `/sensor-api/current`）同样消费 `occupancy / devices.*` 字段，占用指示灯与预测结果联动；
- 即“基线预测结果能在接口（状态对象）中看到，并由 3D 与 Web 端消费”。
