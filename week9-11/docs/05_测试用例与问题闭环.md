### 闭环判定标准（写死，避免“修了但不认”）

1. **修复**：代码合入 + 提交记录（每人至少 1 次提交）；
2. **回归**：对应 TC 由“不通过”变“通过”，并保留执行输出（`results/*.csv`）；
3. **证据**：涉及界面的缺陷必须重新截图（同一分辨率、同一状态）；
4. **关闭**：三项齐全才把缺陷表状态改为“已关闭”，否则只能是“待验证”。

## 五、本轮结论

- 接口层质量：19 条用例 17 条通过，2 条失败均为**实现偏差**（不是设计错误），修复成本低（各 1 行 / 1 个路由）；
- 真实可演示的闭环能力已具备：控制指令往返、历史数据、CSV 导出、图表生成、连续读取零失败；
- 权限/心跳/调度/报告四组用例依赖 Spring Boot + MySQL + Redis 环境，本机缺 Maven，**第 11 周前必须在具备环境的工作站补跑**，否则第 9/10 周的“工程化”只有设计没有验证，会被判证据不足。
