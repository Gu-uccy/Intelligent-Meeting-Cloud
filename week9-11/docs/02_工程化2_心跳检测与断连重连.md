## 二、系统怎样提示

| 状态 | 判定条件 | 界面表现（必须文字 + 颜色双通道） |
| --- | --- | --- |
| 正常 | 最近一次请求 200 且 `timestamp` 落后 ≤ 15 s | 右上角「实时数据 hh:mm:ss」绿色 |
| 数据陈旧 | 200 但 `timestamp` 落后 > 15 s | 黄色横幅「传感器数据已滞后 23 s，当前显示可能不是最新状态」 |
| 断连（首次失败） | 1 次请求失败 | 顶部黄色条「数据获取失败，正在重试（第 1/2 次）」 |
| **断连态** | **连续 ≥2 次失败** | **红色横幅**「接口已断开，数据不可用（最后成功 14:02:31）· 已重试 3 次 · [立即重连]」；场景整体降饱和（`filter: grayscale(0.6)`）并叠加「离线」水印；**控制按钮全部禁用** |
| 已恢复 | 断连态下任一请求成功 | 绿色横幅「已恢复，数据更新至 hh:mm:ss」（3 s 后自动消失），解除禁用与降饱和 |

关键原则：**断连时必须让用户“看得出数据不能用”**，而不是继续展示一份看起来正常的旧场景。

## 四、怎样恢复或处理（实现方案）

### 4.1 后端：新增 `GET /api/health`（向后兼容，不动 v1.0 字段）

```python
@app.get("/api/health")
def health():
    now = time.time()
    age = None if last_sample_ts is None else round(now - last_sample_ts, 1)
    return jsonify({
        "status": "ok" if age is not None and age <= 15 else "degraded",
        "uptime_s": round(now - START_TS, 1),
        "sensor_age_s": age,
        "timestamp": datetime.now().strftime("%Y-%m-%d %H:%M:%S"),
    }), (200 if age is not None else 503)
```

区分两种失败：**进程挂了**（连接失败/404）与**采集挂了**（200 但 `status=degraded`）。

### 4.2 前端：失败计数 + 指数退避 + 手动重连

```js
let failures = 0;
const BASE_INTERVAL = 3000;
const MAX_INTERVAL = 30000;

async function refreshSensorData() {
  try {
    const res = await getCurrentSensorData();
    failures = 0;
    applyData(res);
    setLinkState('online');
    scheduleNext(BASE_INTERVAL);
  } catch (e) {
    failures += 1;
    if (failures >= 2) setLinkState('offline', { lastOkAt: lastUpdated.value });
    scheduleNext(Math.min(BASE_INTERVAL * Math.pow(2, failures - 1), MAX_INTERVAL));
  }
}

function scheduleNext(delay) {
  clearTimeout(sensorTimer);
  sensorTimer = setTimeout(refreshSensorData, delay);
}
```

要点：
1. `setInterval` 改 `setTimeout` 链式调用，才能实现退避（固定间隔无法退避）；
2. 退避上限 30 s，避免长时间不重试；
3. 页面 `visibilitychange` 回到前台立即补一次请求；
4. 断连态下**禁止** `roomState` 使用旧值渲染“正常”样式（保留几何体但整体降饱和 + 水印）；
5. “立即重连”按钮 = `failures = 0; refreshSensorData()`。

### 4.3 服务守护

| 环境 | 方案 |
| --- | --- |
| Windows（本机演示） | 计划任务：`schtasks /create /tn IMC-Sensor /tr "python <path>\unified_meeting_room_system.py" /sc onstart /ru SYSTEM`，崩溃后由 `start-demo.ps1` 的守护循环每 30 s 检查端口，挂了就重启 |
| Linux/树莓派（生产） | `systemd` 服务：`Restart=always`、`RestartSec=5`、`StartLimitBurst=5` |
